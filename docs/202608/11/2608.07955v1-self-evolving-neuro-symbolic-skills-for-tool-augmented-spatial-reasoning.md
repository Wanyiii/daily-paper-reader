## 摘要
大型视觉-语言模型在多模态推理中表现出色，但在细粒度空间任务上仍不可靠，这些任务需要精确的空间感知和超越端到端生成的细粒度几何计算。工具增强提供了一种自然的解决方案，而现有方法要么从头规划工具调用而缺乏显式依赖约束，要么依赖固定流程，导致冗余且跨空间任务泛化能力差。一个有效的空间推理代理应积累可复用经验，并能针对新问题自适应地组合这些经验。为此，我们提出 NeSy-Spatial，一种用于自进化空间技能的神经符号框架。NeSy-Spatial 将工具交互和几何操作抽象为带类型的可执行原子指令，并将其组合为两种互补的技能类型：用于组织工具执行的工具使用技能，以及用于结构化几何推理的几何技能。在推理阶段，NeSy-Spatial 在闭环过程中检索并执行相关技能。在进化阶段，它分析缓冲的成功和失败轨迹，以优化技能结构并剪除不可靠或不活跃的条目。在三个空间推理基准上的实验表明，NeSy-Spatial 通过更精确的工具利用持续提升了推理准确性。

## Abstract
Large vision-language models have achieved strong performance in multimodal reasoning, but they remain unreliable on fine-grained spatial tasks that demand both precise spatial perception and fine-grained geometric computation beyond end-to-end generation. Tool augmentation offers a natural solution, while existing methods either plan tool calls from scratch without explicit dependency constraints or rely on fixed pipelines that are redundant and generalize poorly across spatial tasks. An effective spatial reasoning agent should instead accumulate reusable experience and adaptively compose it for new problems. To this end, we propose NeSy-Spatial, a neuro-symbolic framework for self-evolving spatial skills. NeSy-Spatial abstracts tool interactions and geometric operations into typed executable atomic instructions and composes them into two complementary skill types: Tool-Use Skills for organizing tool execution and Geometry Skills for structured geometric reasoning. During inference, NeSy-Spatial retrieves and executes relevant skills in a closed-loop process. During evolution, it analyzes buffered successful and failed trajectories to refine skill structures and prune unreliable or inactive entries. Experiments on three spatial reasoning benchmarks show that NeSy-Spatial consistently improves reasoning accuracy with more precise tool utilization.

- **现有方法的两类局限**：
  - **动态规划类**（如 SpaAge-ReAct）：从通用工具箱逐查询规划工具调用，灵活但缺乏显式工具依赖和执行顺序约束，容易产生非法工具序列（如在获取物体坐标或点云之前调用 Python）。

### 2. 方法论

#### 2.1 整体框架：NeSy-Spatial

- 提出神经符号技能框架，将工具交互与几何计算统一为可执行原子指令，并组合成高层技能。
- 技能库 `Lib = (A, S)`，其中 `A` 是原子指令集合，`S = S_tool ∪ S_geo` 包含工具使用技能与几何技能。

#### 2.2 原子指令（Atomic Instructions）

- 定义为带类型和局部验证器的可执行操作：`a = (e_a, v_a)`，其中 `e_a: U_a → O_a` 映射输入到输出，`v_a: O_a → {0,1}` 验证输出。
- 分为两类：
  - **工具原子 `A_tool`**：包装视觉工具和 Python 执行器，作为控制器可见动作。
  - **几何原子 `A_geo`**：可复用代码块（坐标变换、距离计算、一致性检查等），在 Python 工具内部执行，不作为独立控制器动作。

#### 2.3 高层技能（High-Level Skills）

- 表示为节点-边-上下文结构：`s = (V, E, κ)`，`V ⊆ A` 原子节点，`E` 执行依赖边，`κ` 实例化上下文。
- **工具使用技能**：节点均为工具原子，编码工具间依赖顺序与上下文绑定，Python 作为原子工具节点以保持紧凑动作空间。
- **几何技能**：节点均为几何原子，内容为可复用、可验证的代码内核（如坐标变换、选项匹配），在 Python 工具内被检索和实例化。

#### 2.4 技能引导的空间推理（推理阶段）

- 循环执行四阶段直至产生答案：
  1. **技能检索**：根据问题与当前状态检索候选技能集 `C_{t,k}`。
  2. **动作选择**：控制器选择停止、激活已检索技能或直接调用工具原子，动作空间为 `{stop} ∪ (C∩S_tool) ∪ A_tool`。
  3. **工具/代码执行**：执行单个原子或技能中下一个依赖就绪节点；Python 原子执行时绑定检索到的几何技能代码块，返回数值结果与验证器结果。
  4. **状态更新**：将观察与验证结果写入工作记忆，更新推理状态。
- 整个过程闭环运行，技能可在任意节点被中断并适应中间结果。

#### 2.5 技能自我进化（进化阶段）

- 当轨迹缓冲区达到 `N_buf` 后，触发批量进化，包含三个模块：
  - **轨迹分析**：从成功与失败轨迹中聚合依赖模式，输出原子更新 `ΔA_t`、支持片段 `Ĝ+` 与无效片段 `Ĝ-`。通过多轨迹聚合减少孤立错误干扰。
  - **技能融合**：将新原子与技能片段与现有库合并，支持添加片段、删除冗余/不兼容依赖、替换子图；应用于统一技能库。
  - **技能剪枝**：根据调用次数 `n_t(z)`、错误率 `ER_t(z)`、不活跃年龄 `Age_t(z)` 与任期 `Tenure_t(z)` 进行判断。剪枝条件为：
    `Prune_t(z) = (n_t(z) ≥ n_min ∧ ER_t(z) > w_t(z)ρ_err) ∨ (Age_t(z) > w_t(z)T_idle)`
    其中 `w_t(z) = 1 + λ·Tenure_t(z)/(1+Tenure_t(z))` 提供任期相关的有界保护，防止新条目被过早剪除。
- 进化只发生在 episode 之间，遵守“先测后更新”协议，避免标签泄漏。
