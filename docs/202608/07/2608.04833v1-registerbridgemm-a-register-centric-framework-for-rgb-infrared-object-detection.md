## 摘要
RGB-红外（RGB-IR）目标检测得益于可见光与热成像模态的互补信息，但在光照变化、天气变化和杂乱场景下，有效融合仍然充满挑战。现有的RGB-IR融合方法往往以表达力强的块级交互为代价，换取更轻量但受限更多的自适应机制。我们通过实验观察到，预训练的寄存器令牌（register tokens）在配对RGB-IR输入上同时包含模态共享与模态特定的信息，这表明它们可以作为跨模态通信的紧凑基础。基于这一观察，我们提出了RegisterBridgeMM，一种以寄存器为中介的融合框架，组织为三阶段寄存器生命周期：聚合（Aggregate）保留从预训练中继承的逐模态寄存器摘要；桥接（Bridge）执行双向的寄存器到块读取，并带有共识残差调节；投影（Project）将所得寄存器摘要转换为对块特征的空间自适应校准。这一寄存器通路避免了密集的块到块跨模态交互，同时保留了预训练的块表示。在两个骨干流均冻结的情况下，RegisterBridgeMM在全部四个基准（LLVIP、M3FD、DroneVehicle和FLIR-Aligned）上取得了所评估方法中最高的mAP50-95。

## Abstract
RGB-infrared (RGB-IR) object detection benefits from complementary visible and thermal cues, but effective fusion remains challenging under illumination changes, weather variation, and cluttered scenes. Existing RGB-IR fusion methods often trade expressive patch-level interaction for lighter but more constrained adaptation mechanisms. We empirically observe that pretrained register tokens contain both modality-shared and modality-specific information on paired RGB-IR inputs, suggesting that they can serve as a compact substrate for cross-modal communication. Building on this observation, we propose RegisterBridgeMM, a register-mediated fusion framework organized as a three-stage register lifecycle. Aggregate preserves per-modality register summarization inherited from pretraining; Bridge performs bidirectional register-to-patch reading with consensus-residual regulation; and Project translates the resulting register summary into spatially adaptive calibration of patch features. This register pathway avoids dense patch-to-patch cross-modal interaction while preserving the pretrained patch representation. With both backbone streams frozen, RegisterBridgeMM achieves the highest mAP50-95 among the evaluated methods on all four benchmarks: LLVIP, M3FD, DroneVehicle, and FLIR-Aligned.

- **问题背景**：RGB-红外（RGB-IR）目标检测利用可见光图像与热红外图像的互补信息，在低光照、恶劣天气、自动驾驶等全天候感知场景中至关重要。RGB提供丰富的纹理和颜色信息，但在弱光、雾天、雨天条件下退化严重；红外则对光照变化不敏感，但缺乏细粒度纹理和类别判别细节。
- **现有方法的局限**：
  - 主流融合方法以**patch token**为融合基元。高保真融合方法计算密集的O(N²) patch-to-patch交叉注意力，在检测分辨率下计算开销随patch数平方增长，成为主导开销；轻量注入方法以主从配置将一模态特征注入另一模态，但非对称结构在辅助模态信息更丰富时（如夜间红外）鲁棒性不足。
  - 现有方法未充分利用预训练ViT内部已存在的紧凑通信通路。
- **核心经验观察**：论文发现，将配对的RGB和IR图像分别通过两个**独立的、未经多模态训练的DINOv3流**时，四个预训练register token并非跨模态一致：三个token的嵌入高度对齐（余弦相似度>0.97），而第四个token发散（余弦≈0.63），构成"3+1"的**模态共享/模态特定**组织。此外，训练后的register-to-patch注意力在深层表现出高度选择性（注意力熵占比从第5层的26%降至第11层的不足1%），且两个方向（RGB→IR和IR→RGB）几乎对称。
- **核心思路**：这些观察表明，预训练register token可作为结构化的跨模态通信基板。论文据此提出 RegisterBridgeMM，将跨模态通信从密集patch交互路由到紧凑的register瓶颈，在保持预训练patch表示的同时实现高效融合。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 整体架构

- 双流结构：RGB和IR输入分别馈入两个**共享权重且完全冻结**的DINOv3 ViT骨干。
- 每个流包含一个[CLS] token、k=4个register token和N个patch token。
- 组织为**三阶段register生命周期**：Aggregate（聚合）→ Bridge（桥接）→ Project（投影）。

### 2.2 阶段I：Aggregate（聚合）

- 不引入新模块，由冻结的DINOv3流天然完成。每个编码器层的register token与同一模态的patch token共同参与自注意力，充当无空间位置的"全局摘要器"。
- 每层register更新可形式化描述为：
  - r_{m,ℓ+1} = SA_ℓ([c_{m,ℓ}; r_{m,ℓ}; p_{m,ℓ}])|_{reg}，其中SA_ℓ为冻结的层ℓ自注意力块，c为[CLS] token，|reg提取register位置输出。
- 前L₀=2层后，各流register已编码独立的单模态全局摘要。冻结该阶段的动机是：预训练的register已具备模态共享/特定分区，可学习的干预可能在桥接之前削弱这一结构。

### 2.3 阶段II：Bridge（桥接）

- 在浅层到中间层 S={2,5,8} 注入桥接模块（与检测头读取的多尺度特征层{5,8,11}解耦）。选择较浅注入层的理由是：被更新的register需要经过后续自注意力层才能影响patch特征；若在第11层注入，则无后续层可传播更新（消融实验验证了这一设计）。
- **RWPR（Register-Write Patch-Read）**：
  - 核心思想：利用register与patch的不对称性。让一个模态的k个register作为query，读取另一模态的N个patch（作为key和value），实现双向交叉注意力，复杂度为O(kN)而非O(N²)。
  - 两个方向的交叉注意力：ΔR = CA_{R→T}(r_{R,ℓ}, p_{T,ℓ}, p_{T,ℓ})，ΔT = CA_{T→R}(r_{T,ℓ}, p_{R,ℓ}, p_{R,ℓ})。
  - 通过sigmoid门控的残差系数 αℓ = α_max·σ(ᾱℓ) 应用LayerNorm更新：r̃_{m,ℓ} = LN(r_{m,ℓ} + αℓ·Δm)，初始α=0.1使桥接在初始时接近恒等映射。
  - 三个特性：（1）复杂度仅占密集patch注意力的k/N比例；（2）深度依赖性读取（信息在最终读取层之前注入）；（3）只更新register，patch token是只读的key/value，保持预训练patch特征流形。
- **RCRS（Register-Consensus/Residual-Split）**：
  - 动机：防止两个流的register无控制地趋同，导致模态特定信号被稀释。
  - 将桥接后的register分解为共识分量和模态特定残差，用可学习标量门控重新混合：
    - cℓ = ½(r̃_{R,ℓ} + r̃_{T,ℓ})（共识）
    - r′_{m,ℓ} = cℓ + βℓ(r̃_{m,ℓ} − cℓ)（共识+缩放残差）
  - βℓ = σ(β̃ℓ) ∈ (0,1)，初始化为0.5。β→0时两模态坍缩为纯共识，β→1时保留原始桥接register。最深注入层的共识向量c*保留用于阶段III。

### 2.4 阶段III：Project（投影）

- **MAC（Modality-Aware Calibration）**：
  - 将register级摘要转换为空间自适应仿射参数，校准patch特征金字塔。
  - 构造CR摘要向量：s_CR = [c̄*; |r̄*_R − c̄*|; |r̄*_T − c̄*|] ∈ R^{3D}，即共识均值+各模态残差绝对值均值。
  - 全局仿射种子：seed_s = W_s·Φ(s_CR)，通过共享两层MLP和逐尺度线性投影生成。
  - 空间信号：通过学习到的模态间gap代理 gap_s = Conv_1×1(F̂_s^R − F̂_s^T) 提供位置特定的不一致线索。
  - 生成SPADE风格仿射参数(γ, β)，输出校准特征：F̃_s^m = F_s^m + α_s(γ_s^m ⊙ F̂_s^m + β_s^m)，其中α_s初始化为0.1，仿射头零初始化，保证初始时为恒等映射。
- **多尺度融合**：逐级拼接+跨尺度残差传播，生成三尺度金字塔供RT-DETR检测头使用。

- **核心发现**：预训练DINOv3的register token在配对RGB-IR输入上天然呈现"3+1"的模态共享/模态特定分区，适合作为跨模态通信基板。
- **方法有效性**：RegisterBridgeMM在两个骨干流完全冻结的情况下，在全部四个基准上取得最高mAP_50-95：
  - M3FD: 92.6 mAP_50 / 64.9 mAP_50-95，超越WaveMamba 0.5点。
  - DroneVehicle: 81.5 / 61.5，超越SLGNet 0.8/1.0点。
  - LLVIP: 98.4 / 70.5，超越GM-DETR 0.3点，参数仅27.8M。

- **跨基准规律**：改进在不同数据集上来自不同机制——LLVIP反映低光行人定位提升，M3FD反映多天气鲁棒性，DroneVehicle上热模糊类别（Truck/Van/Freight Car）增益最大，FLIR-Aligned上反映杂乱场景中的背景抑制能力。mAP_50-95同步提升说明改进不只来自分类置信度，还来自定位质量。
- **效率论证**：k=4时，三层双向桥接仅使用约6kN项注意力，是单个密集patch交叉注意力层N²项的极小比例。
- **训练后register行为变化**：RWPR+RCRS训练后，原本高度对齐的三个token相似度下降（−0.08），发散的第四个token向受调控的共识靠近（+0.25），表明训练重塑了预训练的3+1分区为任务适配的桥接结构。

## 7. 优点

- **问题洞察新颖**：通过预训练register token的跨模态相似性分析，发现了此前未被探索的模态共享/特定组织结构，并据此提出register作为融合基板的新范式，而非沿用密集patch交互或轻量注入的既有路线。
- **架构设计精巧**：
  - 三阶段生命周期组织清晰，每阶段有明确且可解释的功能定位。
  - RWPR的register-to-patch非对称注意力在保留密集空间证据的同时将复杂度从O(N²)降至O(kN)（k=4远小于N）。
  - RCRS将隐式的共享/特定结构转化为显式的代数分解，用可学习标量控制共识-残差权衡。
  - MAC将register级摘要经全局种子+空间gap代理转化为空间自适应仿射校准，解决了register到patch的信息回传问题。
- **参数效率杰出**：双骨干完全冻结，仅27.8M可训练参数，远低于密集融合类方法（如Fusion-Mamba 287.6M），却取得最高精度。
- **工程细节严谨**：门控初始化（α=0.1, β=0.5）、零初始化仿射头、注入层与特征读取层解耦等设计保证了训练稳定性和预训练表示的可保留性。
- **实验验证系统**：涵盖四个不同挑战场景的数据集、逐类别分析、多层次消融、行为诊断和定性可视化，证据链完整。

## 8. 不足与局限

- **算力信息缺失**：未报告GPU数量、训练时间或总计算量，难以评估实际训练成本。
- **消融范围有限**：所有消融仅在LLVIP（单一夜间行人场景）上进行，其他三个数据集上未验证组件泛化性。不同场景下各阶段贡献可能不同。
- **方法适用范围狭窄**：仅验证了DINOv3/DINOv2作为骨干的情境；对基于CNN的骨干或其他ViT变体（如MAE、CLIP）的适用性未知。依赖预训练模型的register token特性，若骨干无register token则无法直接应用。
- **理论上限未探明**：论文声称register通路的效率优势，但未系统对比相同参数预算下的密集patch交互方法，也未分析register数量k对性能/效率的影响。
- **公平性疑虑**：对比方法使用了不同骨干网络和训练配置，论文未报告采用统一训练协议重新实现的对比结果，跨论文的绝对数值比较可能受训练技巧差异影响。
- **实际部署考量不足**：未讨论推理延迟、吞吐量等实时性指标；检测场景（如自动驾驶）对实时性要求高，仅参数数量不足以反映实际可行性。
- **行为分析深度有限**：register的"3+1"组织是否与语义类别有明确对应关系、为何恰好一个token发散等机理问题未深入解释。
